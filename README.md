# Credit Card Fraud Detection — Assignment 3 experiment pipeline

## Research design

Each dataset × 4 resampling conditions (`original`, `ros`, `rus`, `smote`) × 2 classifiers (`logistic_regression`, `random_forest`) produces 8 experiments. The datasets found in `data/` normally produce **24 experiments**.

Every condition uses exactly the same train/test split and set of features for its dataset. Missing-value imputation, feature scaling, and resampling fit on TRAIN ONLY (and separately in each CV training fold when CV is enabled). Test data always retain the original fraud prevalence. Logistic Regression and Random Forest use the same fixed hyperparameters across balancing conditions.

**Important:** Kartik2112 is generated by the Sparkov simulator. It provides `fraudTrain.csv` and `fraudTest.csv` as separate files, so those files stay separate. We intentionally exclude raw categorical variables and IDs from vanilla SMOTE, and create numeric features such as age, transaction hour, and geographic distance. This is a numeric-only baseline, **not** a study of full categorical features. For categorical-aware synthetic resampling, use SMOTENC (a different named algorithm), or establish a suitable, documented representation.

## Where to get datasets

- Kartik2112 (train and test): https://www.kaggle.com/datasets/kartik2112/fraud-detection
- European: https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud
- Miadul: https://www.kaggle.com/datasets/miadul/credit-card-fraud-detection-dataset

The dataset files **are not embedded in this ZIP**; download them from Kaggle, extract the CSV files and place them in the `data/` folder. A possible file layout is:

```
fraud_experiments_project/
  run_experiments.py
  requirements.txt
  data/
    fraudTrain.csv
    fraudTest.csv
    creditcard.csv
    miadul.csv          # Rename the downloaded Miadul CSV if you prefer.
```

## Install on Ubuntu / Linux

```
cd fraud_experiments_project
python3 -m venv .venv

```

## Run every experiment with one command

```
python run_experiments.py --data-dir data --out results
```

The script automatically discovers every `*.csv` in `data/`. If `fraudTrain.csv` and `fraudTest.csv` exist, they are treated as one Kartik dataset with the original train/test split. Every other CSV is processed with the same numeric feature, target validation, stratified split, and resampling pipeline. By default this runs 8 experiments per discovered dataset. Training is capped at 200,000 rows per dataset; the test set is never downsampled.

### Use another data folder

```bash
python run_experiments.py --data-dir /path/to/csv-folder --out results_custom
```

Target columns are detected from common names (`is_fraud`, `fraud`, `class`, `label`, `target`, `y`, and others). For the named legacy datasets, use `--european-target` or `--miadul-target` if automatic detection is not possible.

### More exhaustive experiment (slower, potentially very resource intensive)

```
python run_experiments.py \
  --data-dir data \
  --out results_full \
  --max-train-rows 0 \
  --cv-folds 5
```

On large data, 5-fold cross-validation across 24 configurations can take hours and require considerable RAM/CPU. Start with defaults and expand only after a successful pilot run.

### If the Miadul label is not recognized

Run with `--miadul-target THE_EXACT_COLUMN_NAME`. The script prints all columns in the exception if automatic detection fails. It expects a binary label with 0 = legitimate, 1 = fraud. Do **not** interpret other label codings without checking the dataset documentation.

### Other options

- `--rf-trees 80` and `--rf-depth 16` restrict RF size to manageable settings.
- `--jobs 4` parallel RF workers.
- `--cv-folds 0` by default; use 3 or 5 to run training-only stratified CV.
- `--max-train-rows 200000` or `0` for the full training set.
- `--test-size 0.20` applies to every single-file dataset; Kartik uses its original provided split.

## Results saved to `results/`

- `all_results.csv` — all 24 performance rows (if every experiment runs successfully)
- `all_dataset_summaries.json` — dataset split, class distributions, exact features
- `experiment_config.json` — seed, configurations, library versions
- `experiment.log` — detailed log
- `failures.json` — any failed dataset/experiment (no fabricated scores)
- `<dataset>/dataset_summary.json`
- `<dataset>/class_distribution_train.csv`
- `<dataset>/cm_<model>_<condition>.png` — confusion matrices
- `<dataset>/pr_curve_<model>_<condition>.png` — precision–recall curves
- `<dataset>/comparison_<model>.png` — model comparison charts
- `<dataset>/test_predictions_<model>_<condition>.csv` — original test labels and predicted fraud probabilities

**PR-AUC convention:** the CSV reports `pr_auc_ap`, which is `sklearn.metrics.average_precision_score` (AP: average precision), a standard precision–recall summary. It is not trapezoidal integration of PR curve coordinates.

## Research integrity and limitations

- A successful run is **not** proof that a method is always better or that differences are statistically significant.
- This code does **not** perform hypothesis significance testing; do not claim significance based on observed differences alone.
- We compare *within* datasets; numeric scores across unrelated datasets should not be interpreted as a direct method effect without context.
- European/Miadul are randomly split; if they include time/order or multiple records per entity, a temporal or group-aware split may provide a less optimistic estimate. Inspect each dataset.
- Original paper lists three datasets, but the Miadul schema hasn't been verified in advance. Check emitted feature list and target after downloading.
- Excluding categorical attributes from Kartik reduces available signal; it is a deliberate simplification for standard SMOTE, and should be reported as a limitation.
- The model uses probability threshold 0.5 for precision/recall/F1, without tuning on test. Evaluate threshold sensitivity later if required.
- Since all methods are evaluated against the same test set, treat comparisons as exploratory and avoid repeated tuning on that test set.
- Always cite the Kaggle source of each dataset in your final report.
